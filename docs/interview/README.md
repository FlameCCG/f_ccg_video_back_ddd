## 怎样确认自己理解了

每读完一个主题，合上文档，用自己的话说三件事：

1. **它解决什么问题？** 比如 Kafka 把长时间转码与投稿请求分开，让请求可以在稿件落库后返回。
2. **源码怎样实现？** 比如 `PublishService` 在 MySQL 提交后启动后台任务，经端口与适配器派发转码。
3. **它保证到哪一步？** 请求不等待 Kafka 成功；当前没有事务 Outbox，提交后投递失败仍可能留下没有入队的稿件。

再改变一个条件复述：如果 Kafka 停了呢？如果对象上传成功但写资源行失败呢？如果索引还没追上呢？能说明“已经发生什么、还没发生什么、该查哪里”，才说明你理解了链路。

## 面试练习方法

先练 60 秒项目介绍，再练 3 分钟投稿链路，最后让自己回答 5 个追问：

- 为什么 DDD 不等于四个目录，也不等于微服务？
- 应用层运行时调用 GORM，为什么源码却不依赖 GORM 实现？
- 聚合为什么不是一张表，也不是整个视频业务？
- 投稿成功为什么不代表可播放、已公开或已入队？
- 如果要保证提交后任务可以可靠补投，你准备怎样演进？

DDD 导读和架构图讲解里有对应答案。先独立回答，再对照答案找出漏掉的条件和边界。面试中的项目经历、性能数字和上线效果应以自己的实际工作与测量为依据；文档里的改进方案要明确说成设计建议。
